Extension SDK

Omega Player plays the files already on the phone and ships with no extension. An extension is a small Python module that you write, the user installs, and the app loads only after the user confirms it.

Open the SDK on GitHub Full contract (README.html)

What an extension can add

A search source

Search results in the Search tab, plus the stream and download behind each result. One source at a time, picked by the user.

Music recognition

The app records a few seconds from the microphone when the user presses the button and hands the raw audio to the extension, which does everything after that.

Settings pages

Text fields, secrets, choices, switches, buttons and lists, drawn by the app inside a fixed frame that names the extension.

Several extensions can be enabled at once. Capabilities are detected from the functions a module actually defines, not from what its manifest claims.

Nothing runs without a gesture

An extension runs inside the app's process, with the app's rights. That is why the app treats it carefully:

  • Import is a confirmation. The app shows the name, the version and the SHA-256 fingerprint of the code before anything is installed.
  • The fingerprint is checked at every start. A folder that appeared on its own, or code that changed since the user confirmed it, is never loaded until the user reviews it.
  • Its own data stays apart. An extension writes in its data/ folder, which survives re-imports and is erased with the extension.

Omega Player does not write, review, approve, host or distribute extensions. Whoever installs one is responsible for it, including how it is used under the laws that apply to them.

What is in the SDK

FileRole
media_plugin.pyThe template: a working offline demo source with a settings page. This becomes your extension.
manifest.jsonIts identity: id, name, version.
media_bridge.pyThe app's side of the contract, for reference. Read it rather than guess.
README.htmlThe full guide: functions, return formats, errors, pages and actions, common mistakes.

The same folder can be exported from the app itself, from the Extensions section of the settings.

Getting started

  1. Get the template from the GitHub folder or the export in the app.
  2. Import it unchanged first. It works as shipped: zip media_plugin.py with manifest.json, import the zip from the Extensions settings, then open its page.
  3. Edit and re-import. Your code is replaced, your data/ folder is kept.

The rules that matter

  • Python 3.11, pure Python. Android refuses to load native libraries from a folder the app can write to, so a zip can never carry compiled code. numpy, requests and beautifulsoup4 are bundled with the app.
  • A search source defines search, stream_info, fetch_audio and playlist_meta. An extension without search is fine; one with search but missing the others fails to load.
  • Recognition is recognize(pcm, sample_rate): raw 16-bit mono audio in, a title and artist out.
  • Everything returns JSON and nothing raises. A missing capability or a crash comes back as an error object, never as an exception that breaks playback.
  • Never write in your own code folder: it changes the fingerprint, and the app stops loading the extension until the user reviews it. Use data_dir().
