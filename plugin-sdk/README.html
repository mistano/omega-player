Ce que l'application attend

Un plugin est un module Python nommé media_plugin, chargé dynamiquement depuis filesDir/plugins/<id>/. L'application ne lui parle que par media_bridge.py, fourni à côté, qui appelle les fonctions par leur nom.

FonctionSignatureCapacité
search(query: str, max_results: int = 20, offset: int = 0) -> strsource
stream_info(url: str) -> strsource
related(source_id: str, max_results: int = 10) -> strsource
playlist_meta(url: str, max_items: int = 200) -> strsource
fetch_audio(url: str, out_dir: str) -> strsource
fetch_playlist(url: str, out_dir: str, max_items: int = 200) -> strsource
recognize(pcm: bytes, sample_rate: int) -> stroptionnelle

Trois règles valent pour toutes :

  1. Retourner une chaîne JSON, jamais un dict. Le pont passe la valeur telle quelle à new JSONObject(…) côté Java.
  2. Ne jamais lever. Une exception qui traverse Chaquopy remonte en crash. Une erreur se retourne : {"error": "message lisible"}, et les fonctions de liste ajoutent "results": [] pour que l'appelant puisse itérer sans test.
  3. Bibliothèque standard uniquement, sauf à zipper vos dépendances à côté de media_plugin.py — le dossier du plugin est ajouté à sys.path, rien n'est installé par pip sur l'appareil.

Les capacités ne sont pas déclarées, elles sont déduites

media_bridge.plugin_status() fait callable(getattr(p, "recognize", None)). Définir la fonction l'active, la supprimer la désactive. Le tableau capabilities de manifest.json est documentaire : rien ne s'active en l'écrivant. Côté Java, PluginManager.sait("recognize") relit ce que plugin_status() a déduit, et c'est cette réponse qui commande l'interface.

Sans recognize, les boutons micro restent visibles et cliquables : ils répondent que le plugin actif ne fait pas de reconnaissance et proposent d'aller en installer un autre. Le refus arrive avant le dialogue de consentement et avant la demande de permission micro — l'utilisateur n'enregistre jamais douze secondes pour rien.

Forme d'une piste

Toutes les listes renvoient ce dict (helper _track() dans le squelette) :

{
  "videoId":      "identifiant stable, clé de dédup et de cache vignette",
  "title":        "Titre",
  "channelName":  "Artiste ou chaîne",
  "durationMs":   185000,
  "duration":     "3:05",
  "description":  "300 caractères max",
  "thumbnailUrl": "https://…",
  "url":          "URL canonique, ou videoId à défaut"
}

videoId doit rester stable dans le temps : il sert de clé de déduplication, de clé de cache de vignette, et d'identifiant de téléchargement (dl_<videoId> côté Android Auto et Wear).

Retours par fonction

search        {"results": [piste], "offset": int, "total_fetched": int}
stream_info   piste à plat
              | {"_type": "playlist", "id", "title", "videoCount", "results": [piste]}
related       {"results": [piste]}
playlist_meta {"title": str, "results": [piste]}
fetch_audio   {"filePath", "videoId", "title", "channelName",
               "durationMs", "description", "ext"}
fetch_playlist{"playlistTitle": str, "results": [fetch_audio],
               "errors": [{"videoId", "error"}]}
recognize     réponse brute du service : {"matches": [...], "track": {...}}

fetch_audio : filePath doit exister quand la fonction retourne, l'application l'importe immédiatement. Écrivez les tags dans le fichier si le format le permet — l'application ne le fait pas.

La reconnaissance musicale

L'application ne calcule rien. Elle capte environ 12 s au micro et vous passe le son brut : pcm est un bytes de PCM mono, entiers 16 bits signés, little-endian, à sample_rate Hz (16000 aujourd'hui — lisez le paramètre plutôt que de l'écrire en dur). Relecture sans copie : 

samples = np.frombuffer(pcm, dtype='<i2')

Empreinte, format binaire, service interrogé : tout vous appartient. C'est volontaire — l'application ne doit rien présumer de votre méthode, pour qu'en changer ne demande pas une mise à jour de l'application. Une mise à jour d'application passe par la revue du store ; un plugin ne passe par rien.

NumPy est disponible. Il est embarqué dans l'APK et importable depuis un plugin — contrairement à toute dépendance native que vous zipperiez vous-même, qu'Android refuse de charger depuis un répertoire inscriptible. Servez-vous en : 1500 FFT de 2048 points prennent environ 0,7 s avec, et des dizaines de secondes sans.

Vous recevez du son capté au micro. Il peut contenir autre chose que de la musique : une conversation, une télévision, du silence. Ne l'écrivez pas sur le disque, ne le transmettez pas tel quel, et n'envoyez au réseau que ce que la reconnaissance exige. C'est la pièce de quelqu'un.

L'application lit track.title, track.subtitle et track.images.coverarthq (repli coverart), et n'accepte le résultat que si matches est non vide.

manifest.json

{
  "plugin_version": "0.1.0",
  "capabilities": ["source"],
  "dependencies": {},
  "built_at": "1970-01-01T00:00:00+00:00"
}

plugin_version est l'identité du plugin, pas une décoration : l'application en dérive le dossier d'installation (plugins/plugin_<version>). Conséquence directe — si vous modifiez le code sans changer la version, le dossier existe déjà et l'application ne ré-extrait pas votre zip. Incrémentez à chaque build.

Les autres clés ne sont lues par personne aujourd'hui. capabilities sert la lecture humaine et l'écran Plugins à venir ; gardez-le juste par honnêteté.
