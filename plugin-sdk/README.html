1. Overview and security

An extension is a Python 3.11 module, media_plugin.py, that the app loads inside its own process. It runs with the same rights as the app: network, storage, everything the app can do. Nothing sandboxes it.

That is why nothing runs without a gesture from the user. Importing a zip opens a confirmation dialog showing the name, the version (old → new on an update, with a warning when the new one is older) and the SHA-256 fingerprint of the code. The fingerprint covers every file of the extension except data/ and __pycache__/, and the app checks it again at every start.

StateMeaningLoaded?
EnabledConfirmed by the user, switched on. Any number can be.yes
DisabledConfirmed, switched off. Keeps its settings and data/.no
PendingThe folder appeared without the user importing it (dropped by another extension, for instance).no, until Review
ChangedThe code differs from what the user confirmed.no, until Review
InvalidNo media_plugin.py in the folder.no

Review shows the same dialog as an import. Re-importing an extension replaces its code and keeps its data/ folder. Delete erases the whole folder, data/ included; tracks already added to the library stay.

Never write into your own code folder. A file written there changes the fingerprint, and at the next start the app refuses to load the extension until the user reviews it. Write in data_dir().

2. Several extensions

  • Search source: one at a time, among the enabled extensions that define search. The user picks it from the chips at the top of the Search tab.
  • Music recognition: one at a time, among the enabled extensions that define recognize, chosen on the “Music recognition” row of Settings › Extensions. By default: the search source if it can recognise, else the first enabled one that can.
  • Provenance: every search result remembers the extension that produced it. Opening or downloading that track goes back to that extension (the bridge calls stream_info / fetch_audio with ext=<its id>), even after the user switched to another source. If it has been disabled or deleted, the download fails with a clear message; the app never falls back to another extension.

3. Files and dependencies

files/plugins/<id>/                 your code, as imported (only an import or Review changes it)
files/plugins/<id>/media_plugin.py
files/plugins/<id>/manifest.json
files/plugins/<id>/data/            data_dir(): everything you write
files/plugins/<id>/data/reglages.json   values of your settings pages, written by the app

Before your code runs, the bridge injects three names into your module:

NameWhat it does
extension_idYour id (a string).
data_dir()Creates and returns <your folder>/data. Kept on re-import, erased on delete, excluded from the fingerprint.
reglage(cle, defaut=None)Reads one value of data/reglages.json, fresh at every call.
  • One interpreter for all extensions. Your module is loaded as ext_<id> and your folder is put on sys.path, so your own modules import normally — but they share one namespace with every other extension. Give them unique names (my_extension_api.py, or a package named after your id): two extensions shipping a utils.py hide each other.
  • __pycache__ folders are deleted before every load and no bytecode is written: only the verified .py files run.
  • Bundled with the app: requests, beautifulsoup4, numpy. Import them normally. Anything else must be pure Python, zipped next to media_plugin.py; nothing is installed with pip on the device. If two extensions bundle the same library in two versions, only one is loaded.
  • No native code. Since Android 10 an app may not load compiled code (.so, binary wheels) from a folder it can write to. NumPy is bundled precisely so you can do real signal processing anyway.

4. manifest.json

{
  "id": "my_extension",
  "nom": {"en": "My extension", "fr": "Mon extension"},
  "version": "0.1.0"
}
KeyMeaning
idThe identity of the extension: its folder, its module name, the key of its settings and of its tracks' provenance. Letters, digits, _ and -; anything else becomes _; 64 characters at most. Never change it between versions.
nom (or name)Display name: a string, or {"en": …, "fr": …}; the app picks its own language, else English, else the first entry.
version (or plugin_version)Shown in the confirmation dialog and on the extension's row. Free text; bump it on every release so users can tell versions apart.

Set id. Without it the app falls back on the zip's file name, and a user who renames the zip (my_extension (1).zip) installs a second copy instead of updating the first. With an id, the file name does not matter.

Any other key, including a capabilities array, is documentation only: the app does not read it.

5. Media contract

Signatures, exactly as the bridge calls them:

FunctionSignatureStatus
searchsearch(query, max_results=20, offset=0)makes the extension a search source
stream_infostream_info(url)required with search
fetch_audiofetch_audio(url, out_dir)required with search
playlist_metaplaylist_meta(url, max_items=200)required with search
relatedrelated(source_id, max_results=10)optional (not called by the app today)
fetch_playlistfetch_playlist(url, out_dir, max_items=200)optional (not called by the app today)
recognizerecognize(pcm, sample_rate)optional, see § 8
pagespages()optional, see § 9

An extension that defines search but not the three others fails to load, and its row says which function is missing. An extension without search is fine: it can offer only recognition, or only pages.

The url argument of stream_info and fetch_audio is either a link the user pasted or a sourceId: downloading a search result passes its sourceId. Accept both.

A track

Every list uses this object (helper _track() in the template):

{
  "sourceId":     "stable id: dedup key, thumbnail cache key, download id",
  "title":        "Title",
  "artist":       "Artist",
  "durationMs":   185000,
  "duration":     "3:05",
  "description":  "300 characters at most",
  "thumbnailUrl": "https://…",
  "url":          "canonical link, or the sourceId"
}

sourceId must stay the same over time: it identifies the track in the library, in the download queue, in Android Auto and on the watch.

Return values

search         {"results": [track], "offset": int, "total_fetched": int}
stream_info    track
               | {"_type": "playlist", "id", "title", "artist", "trackCount", "results": [track]}
playlist_meta  {"id", "title", "artist", "trackCount", "results": [track]}
fetch_audio    {"filePath", "sourceId", "title", "artist", "durationMs", "description",
                "format"?}
related        {"results": [track]}
fetch_playlist {"playlistTitle": str, "results": [fetch_audio result],
                "errors": [{"sourceId", "error"}]}
  • search: honour offset; the app asks for the next page with it.
  • fetch_audio: filePath must be an absolute path to a complete file when the function returns, inside out_dir; the app imports it at once. Write the tags (title, artist, cover) into the file if your format allows it: the app does not. format ("m4a", "mp3"…) is informational and not read by the app; older templates called it ext, which is ignored just the same. Prefer m4a, mp3, flac or opus.

Field names and legacy aliases

Older extensions used other names. The bridge still accepts them, but set only the new name:

Set thisLegacy names, still accepted
sourceIdvideoId
artistchannelName, uploader
trackCountvideoCount

The bridge copies the new name onto the legacy one when the legacy one is missing, and never overwrites a value you set. If you set both, the legacy value is the one the app reads.

6. Errors

  • Return an error, do not raise one. {"error": "readable message"}: the app shows your text as is, so write it for the user. List functions may add "results": [].
  • An exception never crashes the app. The bridge catches everything (including SystemExit) and answers {"error": "extension_error", "message": "ValueError: …"}: the type and message only, never a traceback. Same at import time: a SyntaxError shows on the extension's row and the extension is not loaded.
  • Return a JSON string, a dict or a list; the bridge serialises the latter. Strict JSON only: NaN and infinity are refused.

Codes the bridge itself may return:

CodeWhen
extension_errorYour code raised, at import or during a call. message = "Type: message".
unsupportedThe function is not defined (no recognize, no pages…).
no_pluginNo search source, or the named extension is not loaded.

7. Capabilities are detected, not declared

The bridge checks callable(getattr(module, name, None)). Define search and the extension is a source; define recognize and the microphone buttons can use it; define pages and “Open its page ›” appears on its row. Remove the function and the capability is gone. A capabilities array in manifest.json is purely documentary: nothing switches on by writing it.

Without a recognition extension, the microphone buttons stay visible and explain what is missing. That check runs before the consent dialog and before the microphone permission prompt: nobody records twelve seconds for nothing.

8. Music recognition

The app computes nothing. It records about 12 s from the microphone and calls recognize(pcm, sample_rate):

  • pcm: bytes of raw PCM, mono, signed 16-bit little-endian, no header;
  • sample_rate: samples per second, 16000 today. Read it, do not hard-code it.
import numpy as np
samples = np.frombuffer(pcm, dtype="<i2")

Fingerprint, format, service: everything after that is yours, so changing method or provider never needs an app update. Return only the result: 

{"title": "…", "artist": "…", "artworkUrl": "https://…"}   # artworkUrl optional
{"match": null}                                            # nothing recognised
{"error": "readable message"}                              # failure

The app shows the title and artist, and its button runs a search for them in the Search tab; it downloads nothing by itself.

NumPy is available. It ships inside the app and imports normally — unlike any native dependency you would zip yourself. 1500 FFTs of 2048 points take about 0.7 s with it, tens of seconds without.

You receive microphone audio. It may hold something other than music: a conversation, a television, silence. Do not write it to disk, do not forward it as is, and send over the network only what recognition requires. It is somebody's room. Return {"match": null} rather than a guess.

9. Pages and actions

pages() describes screens that the app draws with its own native components: never HTML, links or prices. It returns a list of pages: 

def pages():
    return [{
        "id": "settings",
        "titre": {"en": "My extension", "fr": "Mon extension"},
        "elements": [
            {"type": "texte", "cle": "server", "libelle": "Server", "aide": "https://…"},
            {"type": "interrupteur", "cle": "hq", "libelle": "High quality", "defaut": True},
            {"type": "bouton", "libelle": "Test the connection", "action": "test_connection"},
        ],
    }]

def test_connection(reglages):
    ok = bool(reglages.get("server"))
    return {"message": "Connected." if ok else "No server set.", "rafraichir": False}

The eight element types

TypeFieldsWhat the user sees
textecle, libelle, aide?, defaut?A text field, saved under cle.
secretcle, libelle, aide?A masked field (password, token). Never logged, exported or backed up by the app.
choixcle, libelle, valeurs, defaut?A drop-down. valeurs: strings, or {"valeur", "libelle"}. Values keep their type (number, boolean, text).
interrupteurcle, libelle, aide?, defaut?A switch.
boutonlibelle, action, arg?A button calling one of your functions.
messagetexteA paragraph.
listeelements: {titre, sous_titre?, vignette?, bouton?}A list of items, each with an optional thumbnail and button.
pagecible, libelleA link to another page (id) of the same extension.
  • defaut (on texte, choix, interrupteur): what the field shows until the user saves something. It is not saved, so reglage(cle, defaut) still returns its own defaut argument: use the same default in both places, or a switch your code treats as on will be shown off.
  • Text: a string, or {"en": …, "fr": …}. The app picks its exact language (pt-BR → pt_br), else a variant of it, else English, else the first entry.
  • vignette: a PNG or JPEG in base64 (data: prefix optional), or a path relative to your folder (refused if it leads outside). Never a URL: the app fetches nothing.
  • An unknown type shows as a grey “not supported” line; it never crashes the page.
  • Values are saved by the app in data/reglages.json at every change; read them with reglage(cle, defaut). If that file is unreadable, the app writes nothing over it and says so.

Actions

  • A button calls the top-level function named by its action, as fn(reglages), or fn(reglages, arg) when the button has an arg. reglages is the dict of saved values.
  • Allow-list: pages() is read again at every call, and only the action of a button the app actually displays may run. Never a name starting with _, nor a reserved name: reglage, data_dir, extension_id, search, stream_info, fetch_audio, related, playlist_meta, fetch_playlist, recognize, pages. A button whose action would be refused is shown as “not supported”.
  • Return {"message": str | {lang: str}, "rafraichir": bool, "page": id}, every key optional, or None. rafraichir re-reads pages() first; page then opens that page.
  • Time limits: reading the pages, 5 s (then a Retry button). An action, 15 s: after that the app says the extension did not respond and the action may still be running; the buttons stay disabled until the real return. One action at a time per extension.
  • Limits: the first 50 pages, 200 elements per page, 200 list items per page (with an “N items not shown” line beyond).
  • No component opens a URL, shows a price or enables an extension. That is deliberate.

Dropping another extension

An extension may act as a catalogue and drop another one (or any file) into files/plugins/ or its own data_dir(). Copy with shutil.copyfile, file by file and without metadata: copytree, copy2 and copystat copy the SELinux extended attributes and Android refuses (relabelfrom). A dropped extension is Pending: it never loads until the user reviews and confirms it.
